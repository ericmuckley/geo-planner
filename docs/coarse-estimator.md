# Coarse nationwide estimator

Implemented October 22, 2026 as the first slice of the user's product reset: a simple fullstack Vercel app estimating long isochrones from arbitrary contiguous-US land origins, with refinement later. The main page defaults to this model at six hours and offers six-, ten- and twelve-hour presets. The connected provider and detailed regional experiment remain available separately.

## What the model does

The TypeScript server searches a **0.1° geographic grid** over `[-125,24,-66,50]`. Cells are about **7–11 km** across, depending on latitude and direction. This is display resolution, not a measured spatial or travel-time error bound. A land mask limits general travel to the US; lake cells are removed. Natural Earth's generalized US road lines add faster, bidirectional links between neighboring cells.

| Travel | Assumed speed |
| --- | --- |
| General land travel, including land without roads | 25 km/h |
| Major highway | 90 km/h |
| Beltway | 80 km/h |
| Bypass | 70 km/h |
| Secondary highway | 65 km/h |
| Other retained road | 45 km/h |

Bounded Dijkstra search uses geographic center-to-center distances. Overland diagonals require both adjacent orthogonal land cells. Road-only water cells permit explicit generalized bridge alignments; they do not gain general overland neighbors. Nearby roads and grade-separated crossings merge within cells. Speeds are assumptions, not fitted measurements.

Origin validation uses the generalized US boundary and lake polygons with a **1 km boundary tolerance**. The origin's own cell is treated as land for that query, including small islands whose cell center is water. Initial cost estimates access to its cell center at 25 km/h; no island is silently snapped to the mainland. Filled MultiPolygons trace reached land cells, preserving holes and disconnected components. Small isolated islands can return only one cell for every budget. Ferries and international crossings are excluded; US-only source features and a coarse mask do not constitute a precise border-access model.

The endpoint accepts **60–720 whole minutes**. It returns explicit approximation warnings, model/source versions, reached-cell count, origin attachment distance and separate grid-search/contour timings. `coverageVerified` remains false. Shading does not establish an accessible road at every point. Traffic, one-way roads, turns, terrain, gates and actual access are not modeled. Travel-time accuracy has **not** been calibrated.

## Data and deployment

The bundled artifact is [coarse-grid-v1.json](../src/server/data/coarse-grid-v1.json), generated by [the offline builder](../scripts/build-coarse-grid.py). It has 153,400 cells, 81,450 center-on-land cells, 6,391 contributing road features and 33,398 undirected road links. The JSON is **1,801,439 bytes**, SHA-256 `7dfd3b30965c21a57fcca408a97a4d95e455bda33d09ecc7a29953346c23d8c4`. Two builds from the pinned inputs produced identical bytes.

Sources are the roads, countries and lakes GeoJSON files in the official Natural Earth repository at tag **v5.1.2**. Source URLs and SHA-256 values are embedded in the artifact and enforced by the builder. These are **generalized cartographic data, not a current routable road inventory**. Natural Earth data are [public domain](https://www.naturalearthdata.com/about/terms-of-use/); see the [road dataset description](https://www.naturalearthdata.com/downloads/10m-cultural-vectors/roads/).

The artifact is a normal source file intended for Git and deployment. The 68.8 MB raw inputs live in ignored `data/coarse-sources/natural-earth-v5.1.2/`; they are needed only to regenerate it. [Local development](local-development.md#regenerate-the-coarse-grid) gives exact downloads and build commands.

`GET/POST /api/estimate` runs inside the existing TanStack Start/Nitro app, including the generated Vercel handler. It needs no database, Python, Docker, local worker, routing-service key or network fetch. Decoded arrays are reused within a warm process; each query owns its labels and contour mask. The browser still downloads its basemap independently. Database-backed saved history is now implemented as a separate API without moving estimation into PostgreSQL or introducing PostGIS; see [saved-history setup](local-development.md#saved-history-api). The original evidence below precedes that follow-up, which is recorded in [current implementation status](implementation-status.md#saved-history-verification).

## Verification and remaining work

[The October 22 evidence](evidence/coarse-estimator-2026-10-22/README.md) records:

- 26 passing server tests, including synthetic water/bridge, speed, budget, island isolation and contour-hole cases, national origins, invalid requests and zero routing fetches under `VERCEL=1`.
- 42 successful sequential in-process cases: fourteen city/rural/coastal/border/island origins at 6/10/12 hours, increasing reachable-cell counts and responses below 1 MB. This is a smoke check, not independent route-time validation.
- Check, typecheck, ordinary production build and Vercel-target build pass. Biome retains the existing database non-null-assertion warning.
- The generated Vercel handler returns filled results for San Diego 6h, Denver 10h and New York 12h with outbound fetches rejected. The detailed local endpoint remains disabled. The function is about 5.3 MB; the grid is absent from public JavaScript, and raw source/worker/environment files are absent from the function.
- Browser flows cover default six-hour computation, New York twelve-hour computation and saved coarse replay across model selection. Browser and server timing scopes remain separate.

No Vercel cloud deployment has occurred. Local handler tests do not measure cloud cold starts, concurrent request behavior or peak memory. Process-memory snapshots and local timings in the raw evidence are observations, not production budgets. Before release, deploy a preview, repeat representative computations there, and assess cloud resources. Then compare a small set of known routes/barriers against an independent reference, record the largest discrepancies and refine the most consequential assumptions. Do not make refinement depend on restarting detailed regional graph expansion.
