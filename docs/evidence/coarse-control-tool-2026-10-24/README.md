## Capture and replay

The new producer versions the bounded capture mechanics used by the earlier 48-query tool. That sealed producer is not refactored or edited. Inspection verifies the six-query plan hash, both original reference-comparison hashes, and every saved Valhalla duration/distance and OD coordinate. CLI `--check` and `--replay` never load dotenv, read ORS_API_KEY or call the network. Only explicit `--capture <fresh-directory> --confirm-6-requests` loads existing server-only configuration. The old 48-request confirmation flag cannot authorize this command.

Capture fixes the endpoint and six bodies, limits itself to six POSTs with at least 6.5s between starts and a 45s deadline covering response headers/body, and refuses directory reuse. No retries, redirects, resume, fallback, auth/status probe or paid upgrade. 401/403/429, zero returned remaining quota or a 2MB raw-body limit stop the run. File-write failure stops further requests. Known credential echoes are redacted from retained response text/allowed headers; raw exceptions use fixed safe diagnostics. Partial bodies survive timeouts. Numeric filenames prevent fixture IDs from becoming paths.

Every attempted request/body/result and all six attempted/skipped ledger entries are checksum-bound. Replay checks file completeness, exact request/hash bindings, timing/spacing, stop behavior, response bytes, ledger order and protocol limits; it rejects extra files, even a checksum-bound seventh request outside the ledger. Interrupted directories cannot resume or replay as complete runs. Generated reports stay outside sealed capture directories. Capture records whether transport was live or injected/synthetic, so fixtures cannot masquerade as measured provider output.

Replay preserves all six denominators and reports signed/absolute/percentage ORS-minus-Valhalla timing differences, route-distance differences, reference engine/data versions and endpoint snaps. Snap>100m remains in the primary results, with a separate <=100m subset. The frozen exploratory flag uses at least four differences >=5min and median signed difference >=5min. Missing pairs or large snaps remain explicit and limit interpretation; a false flag does not prove agreement. The flag is not a model acceptance gate and never applies a routing correction.
