## Current semantics and limits

The selected hosted path uses openrouteservice `driving-car`, outbound start locations, seconds and smoothing 0; other costs use provider defaults. It enforces 60 minutes and retains reported provenance/attribution. Real hosted smoke queries and the browser flow succeed; independent route/snapping qualification is pending. See [hosted findings](hosted-routing-verification.md).

The retained local reference is **Valhalla's default auto-profile time-contour baseline**, with `freeflow` and `constrained` speed sources, no requested date/time, outbound expansion, polygon output, 100 m contour generalization, and denoise 0 (retain disconnected contour components). Other access preferences and penalties use the engine's defaults, so record the actual engine build. It is not yet independently verified minimum-time graph reachability. Filled contour membership does not establish road access to every shaded location.

The default graph requests `[-119.8,30.8,-114.5,35.5]`, using Southern California/Mexico roads and complete US/California/Mexico administrative relations. Road and supplementary-admin acquisition dates differ. San Diego `/locate` confirms US/CA; sampled contours also work in Los Angeles, Bakersfield and Ensenada. Rosarito still takes 66.20 modeled route minutes despite its endpoint lying inside the 60-minute contour; four coarse 60→120 nesting misses remain. The grid depends on maximum budget, but exact graph membership remains unverified. No live border waits, traffic, or timezone DB are provided. See the [expansion report](routing-expansion-verification.md).

The local Valhalla adapter defaults to a 120-minute cap; the selected hosted openrouteservice adapter enforces 60 minutes. The query schema permits up to 720 minutes, but the server also enforces `VALHALLA_MAX_MINUTES`. Raising this value does not change the engine configuration or expand its graph. Optional `VALHALLA_COVERAGE_BOUNDS` rejects origins outside declared bounds (including date-line-crossing boxes). Bounds do not establish complete roads or journeys. Coverage is an operator-supplied label, and every response currently records `coverageVerified: false`; there is no automatic boundary-truncation detector. Map input latitude is limited to ±85° for the initial Web Mercator workspace.

Road-mile, straight-line-distance, union/intersection, and same-path dual-budget queries are not implemented. These definitions remain separate in the initial plan. Database-backed history, PostGIS, POIs, land overlap, DEM masks, multi-contour output, production native routing, interactive query caching, tile overlays, and long-range correctness/performance measurements are also pending. The offline pilot retains coordinate matrices; it does not implement these capabilities.
