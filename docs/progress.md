# Where Geo Planner stands

Updated October 22, 2026. The app now has a first **coarse contiguous-US estimator**, independent of routing-provider quotas.

- **Working:** choose a US land origin, compute a filled six-, ten- or twelve-hour estimate, inspect model warnings/timings, save/replay cloud-backed queries and runs and export JSON. Start with `npm run dev`; no database, worker, Python, Docker or routing API key is needed.
- **Small deployment:** a bundled 8.00 MB road-informed grid runs inside the existing TypeScript server. The generated Vercel function is about 13.45 MB and computes contours locally with outbound fetches rejected. The user accepted the earlier deployed v3 baseline. V4 is verified locally and ready for deployment; cloud resources remain unmeasured.
- **Deliberately coarse:** 7–11 km display cells, generalized Natural Earth roads, assumed 25 km/h land travel (including places without roads) and 55–105 km/h major roads. Traffic, turns, terrain, precise road access, ferries and international crossings are unmodeled. Display resolution is not an accuracy guarantee; national driving-time accuracy remains unvalidated.
- **Checked:** 45 server tests, eight geometry tests, 42 national origin/budget smoke cases and local Vercel execution pass. Biome, typecheck and both builds also pass. Earlier unchanged-history checks cover live PostgreSQL persistence/isolation/concurrent-merge/retention and browser save/reload/model replay. These establish software behavior and local packaging, not real travel-time accuracy or cloud performance. [Model and evidence](coarse-estimator.md).
- **Cloud history works:** the reviewed additive migration is applied to the configured cloud PostgreSQL database. New saves back up automatically; existing browser history uploads through the backup button. Twenty summaries are private to each browser; local saving/export and retry remain available. No accounts or cross-device sync yet. [Evidence](evidence/saved-history-2026-10-22/README.md).
- **General shore correction:** v3 adds 1,535 mixed-cell land representatives, 4,599 checked local shore links and 245 retained-road access points, with speeds unchanged. There are no city/coordinate exceptions. All 24 regional sample destinations are now reached; original eleven costs stay unchanged. Common-case point mean difference improves 37.7m → 36.9m versus v2, two cases improve and none regress. The newly reached trip is still 146.0m versus a 61.3m reference, so missing-road/time accuracy remains open. [Findings](coarse-estimator.md#v3-general-shore-connectivity).
- **Access diagnosis complete:** all 35 saved point costs are reconstructed. Palm Springs–Idyllwild spends 35.1m on endpoint access; a source road is only about 30 metres from Palm Springs. Big Bear/Bombay Beach instead have no source road within about 30/23 km and incur long assumed local travel. [Evidence](evidence/coarse-access-2026-10-22/README.md).
- **Road attachment implemented:** v4 charges local access plus actual retained road geometry at existing class speeds. All v3 graph/shore data remain unchanged. Original point mean reference difference improves 31.4m → 22.2m (11/11 cases); broader mean improves 38.9m → 34.2m across all 24 cases (20 improve, four unchanged). No sample regresses; these are development comparisons, not national accuracy validation. [V4 findings](coarse-estimator.md#v4-charged-road-attachment).
- **Next:** deploy v4, then prioritize missing roads with a compact source improvement. One source-road visit per cell still limits local access; no named-route exceptions or deployment redesign. Credentials stay server-only or ignored.
- **Preserved reference:** the detailed two-hour regional OSM engine remains at `/experiment`. Its exact rebuild/proofs pass, but longer regional expansion and memory optimization are parked. The separate connected-provider option retains its hosted 60-minute cap. [Detailed baseline](two-hour-region.md) and [memory result](six-hour-preflight.md#memory-follow-up).
